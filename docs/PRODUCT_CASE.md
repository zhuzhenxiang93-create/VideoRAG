# 产品案例：从教程中找到可核实的一步

## 用户与任务
目标用户是学习 Photoshop 等软件、卡在具体操作的人。典型任务：“保存成 PDF，同时保留可编辑图层”。用户需要步骤、按钮或参数，以及原教程的时间位置。
这属于需求假设，尚无用户访谈验证。用户语言偏好、查找基线耗时、生成答案相对直接看片段的价值、误拒答接受度都未测量。

## MVP 与取舍
实现问题输入、可选视频范围、片段检索、带引用回答、播放器定位和完整状态，复用 Flask 和原生前端。默认不预先给模型正确视频；范围过滤在召回前生效。
不包含通用视频平台、自动剪辑、多租户、支付或复杂 Agent，因为尚不能证明它们改善核心查证任务。

## 交互理由
- 时间证据使用户能核实按钮位置和操作顺序。
- 拒答避免把“模型有输出”误判为成功。
- 全库默认适合未知教程的提问；可选范围降低同名操作歧义。
- 双入口把“定位”和“理解”分开，减少不必要生成等待。
- 双栏方便对照，小屏单列；长 ASR/OCR 按需展开。

## 指标
离线分别看正确视频/时间片段 Recall@1/5、冻结候选池精排收益、Token F1、引用有效率、证据命中率和平均/中位数/P95 延迟。正时间重叠是宽松判据，不能替代人工核对。
计划中的体验指标（未测）：任务耗时、首次找到正确证据比例、证据点击率、独立完成率、误答/误拒答反馈。计划让目标用户完成同样操作任务，对比手动拖视频与查证助手。没有虚构用户规模、留存、收入或节省时间比例。

## 实际失败
2026-09-07，问题 dev:1168 “how can i save my file as a pdf file?” 返回 HTTP 200，却拒答且引用为空；官方答案区间 76.27–102.92 秒。当时完整验收失败。[原始记录](../reports/tutorialvqa/2026-09-07/api-report.json)。
这说明接口成功与任务完成必须分开。后续历史 5 视频范围测试改善，不代表新全库链路已解决。当前 BM25 页面检索能找到 14643 的 75 秒片段并播放，也只证明检索和定位。
改进：分别排查错视频、窗口偏移、OCR 缺失、精排错序及生成误拒答，保存候选池和引用时间，人工回看后再决定扩充上下文或改排序。19048 待审批，尚无新精排收益结论。

## 本次作品集边界
可展示真实工作台、76 视频 BM25 检索、范围与播放、历史指标和浏览器测试。待补至少 3 条真实跨视频模型问答、人工核对、无关问题拒答、模型范围约束、新指标及获授权的完整录屏。
